# Статьи Lambert/Digital: Pages CMS

## Как устроена публикация

Pages CMS редактирует только коллекцию **«Статьи»** из `.pages.yml`. Контент хранится в `content/articles/*.yml`, изображения — в `assets/images/articles/`. Затем Node.js-генератор читает и валидирует источники, создаёт HTML статьи, карточки каталога, SEO/JSON-LD и обновляет только URL статей в `sitemap.xml`. GitHub Actions запускает тесты и сборку перед единым деплоем GitHub Pages.

Файлы `.yml` записаны в JSON-синтаксисе: JSON является допустимым YAML 1.2, Pages CMS показывает их как обычные поля, а сборка не требует сторонних npm-зависимостей. Это делает `npm ci` быстрым и надёжным.

## Первый вход в Pages CMS

1. Откройте [Pages CMS](https://pagescms.org/) и войдите через GitHub.
2. Разрешите сервису доступ к репозиторию `lambert34/ai-seo-land`.
3. Выберите репозиторий и основную ветку. CMS автоматически прочитает `.pages.yml`.
4. Откройте **Статьи**. Другие страницы сайта в конфигурацию CMS не включены.

Pages CMS не умеет штатно показывать диалог-предупреждение именно при изменении slug уже опубликованной записи. Поэтому возле поля есть постоянное предупреждение: изменение slug меняет URL; необходимый редирект следует настроить отдельно. Динамическая папка media по slug тоже не используется: изображения получают уникальные имена в общей папке.

## Создание и редактирование статьи

1. Нажмите **Новая статья**.
2. Заполните заголовок, краткое описание и категорию.
3. Укажите `slug`: строчные латинские буквы, цифры и одиночные дефисы, без дефиса в начале/конце. Он формирует `/articles/{slug}/` и должен быть уникальным.
4. Укажите дату публикации. `dateModified` меняйте только при реальном содержательном обновлении. Такой детерминированный подход не объявляет старые материалы обновлёнными при каждой пересборке.
5. Заполните обязательный **SEO Description**. SEO Title необязателен: fallback — `{Заголовок} | Lambert/Digital`. Canonical вычисляется автоматически. OG Image необязателен; fallback — `/assets/images/A.png`.
6. Добавьте вступление и упорядоченные блоки, перетаскивая их в нужном порядке.
7. Оставьте статус `draft`, сохраните и проверьте данные. Черновик валидируется, но не получает HTML, карточку или URL sitemap.
8. Когда материал готов, выберите `published` и сохраните. Commit CMS запустит Actions; после успешной сборки статья появится на сайте.

## Блоки

- **Текст** — безопасный rich text: абзацы, выделение, ссылки и inline code. Скрипты, inline-обработчики и исполняемые URL запрещены на build-time.
- **H2 / H3** — заголовок и необязательный anchor. Все H2 автоматически попадают в содержание. Пустой anchor транслитерируется; коллизии получают `-2`, `-3`.
- **Список** — массив элементов и переключатель нумерации.
- **Изображение** — файл, обязательный alt, необязательные подпись/width/height. Генератор добавляет lazy loading. Автоконвертация WebP/AVIF намеренно отложена: она потребовала бы рискованной native-зависимости.
- **Врезка**, **код**, **цитата**, **responsive-таблица**, **разделитель**.
- **CTA** — заголовок, описание, кнопка, URL и тип. `internal` открывается в текущей вкладке; `external` получает `noopener noreferrer`; `affiliate` — `sponsored noopener noreferrer`. Для Zarub укажите tracking `zarub-referral`: сохранится `data-metrika-click`, а существующий `js/main.js` отправит отдельную цель `zarub_referral_click`.
- **FAQ** — видимые пары вопрос/ответ. Только при наличии этого блока создаётся дословно соответствующий `FAQPage`.

## Сборка и проверка

```bash
npm ci
npm run build:articles
npm run test:articles
```

Генератор проверяет обязательные поля, slug и его уникальность, категории/status/robots, структуру блоков, alt изображений и безопасность URL/HTML. Критичная ошибка завершает сборку строками `ERROR: файл` и понятным описанием. Предупреждения (например, ссылка на `chatgpt.com`) не переписывают источник.

Время чтения — количество слов в содержательных блоках, кроме кода, по 190 слов/минуту, минимум одна минута; русское окончание выбирается автоматически. Каталог сортируется по `datePublished` по убыванию. В sitemap входят только опубликованные `index, follow`; коммерческие URL сохраняются. `demo-article` остаётся статическим `noindex` и никогда не входит в CMS/каталог/sitemap.

## Какие файлы нельзя редактировать вручную

Источник истины — **только** `content/articles/`. Не редактируйте вручную:

- `articles/index.html`;
- `articles/{slug}/index.html` для CMS-статей;
- статьевую часть `sitemap.xml`.

Эти outputs хранятся в Git для сохранения текущей branch-based совместимости, но CI всегда пересобирает их из source перед публикацией. Комментарий `Generated from CMS content` дополнительно отмечает generated HTML. Шаблоны находятся в `templates/`, логика — в `scripts/build-articles.mjs`.

Если Actions сообщает ошибку, откройте упомянутый source в Pages CMS, исправьте конкретное поле и сохраните снова. Не исправляйте сгенерированный HTML: следующая сборка его перезапишет.
